Сравнение гостиничных тарифов с фильтрами по географии, звёздам и условиям.
Тот же интерфейс работает на телефоне и компьютере без входа.

## Текущий срез

Наблюдения от 25 ноября 2026. Проживание 27–29 ноября 2026: два взрослых, один номер.
Выборка — 150 отелей (80 в России, 70 за рубежом). Сохранено 544 наблюдения:

| Площадка | Проверено карточек | С ценами | Нет номеров | Тарифов |
| --- | ---: | ---: | ---: | ---: |
| Отелло | 150 | 137 | 13 | 3 243 |
| Островок | 148 | 134 | 0 подтверждённых | 4 520 |
| Ozon | 122 | 110 | 12 | 1 933 |
| Яндекс | 124 | 110 | 12 | 4 191 |

Всего 13 887 предложений. У Островка 12 ответов без цены и два с валютой,
отличающейся от RUB; пустой ответ не считается отсутствием номеров.
У Яндекса проверены все 124 найденные ссылки: одна возвращает «страница не найдена»,
ещё одна перенаправлена на другую страницу и требует проверки сопоставления.
Для 26 отелей ссылка Яндекса пока не найдена. У Ozon проверены все 122 найденные
карточки; ещё 28 ссылок отсутствуют. Неполное покрытие отмечено отдельно;
старые цены не подмешиваются.
Графические цены без подтверждённого обозначения Яндекс Пэй не классифицируются
по предположению и не входят в расчёт.

В предварительном режиме «Все цены» участвует 311 пар отель × конкурент:
191 потенциальный проигрыш Отелло, 53 преимущества, 67 равных минимумов.
В публичном режиме — 206 пар: 107 / 38 / 61 соответственно.
Известные доплаты, спорные объекты и пропуски исключены.
Строгих подтверждённых сравнений нет. Реестровый ID служит сопоставлению
и не показывается в таблицах. Неизвестные условия не считаются различающимися.

Все извлечённые цены показаны с условиями доступа; оплата частями Отелло
не попадает в публичную базовую цену. Предыдущие опубликованные срезы
сохранены в истории. Исходные ответы, cookies, токены, личные данные сессий
и SQLite не публикуются.

## Регулярный мониторинг

Обновляется существующий дашборд: тарифы, статистика, карты и Excel.
Отдельной сводки для команды коммерции нет. Прошлые замеры доступны по ссылке
«Предыдущий срез», исходные наблюдения сохраняются отдельно и не перезаписываются.

План: раз в две недели по понедельникам в 09:00 Europe/Moscow, начиная с
30 ноября 2026. Сценарий каждого запуска — ближайшая пятница–воскресенье,
две ночи, два взрослых, один номер, сумма в RUB за весь период.
30 ноября → 4–6 декабря; 14 декабря → 18–20 декабря.
План хранится в config/monitoring.json. Автоматизация Codex запускается на компьютере;
для исполнения Mac и Codex должны быть доступны. GitHub Pages только показывает
опубликованные файлы и сам цены не собирает.

Отелло и Островок: обычные анонимные HTTP-запросы по сохранённым ID конкретных отелей.
Без поиска по городскому топу и без смешивания цены одного тарифа с условиями другого.
Итог Отелло берётся из total, не из округлённой цены за ночь. Оплата частями выделена
отдельно от публичной цены. Островок подтверждает ID и размещение; даты связаны с
принятым запросом, но не повторяются в ответе. Такие наблюдения разрешены только
для предварительного сравнения, не для строгих совпадений.
Яндекс и Ozon пока требуют отдельного сбора на те же даты. Старые цены в новый
срез не подмешиваются. CAPTCHA, вход и ограничения запросов не обходятся.

Из корня рабочего проекта:

```bash
PYTHONPATH=src .venv/bin/python -m rate_shopper.cli.refresh --output ../hotel-report/updates
```

Код возврата 1 означает PARTIAL_SUCCESS (например, две площадки ожидают обновления),
2 — FAILED. Неудачный запуск не меняет latest.json и опубликованный сайт.
Не запускайте второй сбор параллельно первому. Блокировка .refresh.lock удаляется
после штатного завершения; после аварийного закрытия сначала убедитесь, что процесса нет.

Пилот: добавьте --pilot; проверка суммы за три ночи: --pilot --nights 3.
Текущий рабочий режим остаётся двухночным. У каждого запуска свой каталог
data/monitoring/<run-id> с hotel/scenario-конфигами, исходными ответами и manifest.json.
Точный путь готового отчёта записан в ../hotel-report/updates/latest.json.
История метаданных — data/monitoring/history.sqlite3.

Повтор разбора сохранённых ответов без новых запросов:

```bash
PYTHONPATH=src .venv/bin/python -m rate_shopper.cli.refresh --replay data/monitoring/<run-id> --output ../hotel-report/updates
```

Excel строится существующим scripts/export-xlsx.mjs из того же report.json.
В Codex используйте Node и @oai/artifact-tool из load_workspace_dependencies.
В рабочем каталоге создайте node_modules-ссылку на выданные bundled dependencies;
не устанавливайте пакет поверх них. Затем:

```bash
node scripts/export-xlsx.mjs ../hotel-report/updates/<run-id>
PYTHONPATH=src .venv/bin/python -m rate_shopper.reporting.update ../hotel-report/updates/<run-id> ../hotel-public/site
```

Экспортёр проверяет пересчёт формул и сохраняет workbook-manifest.json.
Публикатор сверяет контрольные суммы отчёта и Excel, отказывает при FAILED
и сначала сохраняет прошлую очищенную версию в site/history/<snapshot-id>.
Сырые ответы и SQLite не публикуются. Все страницы получают один и тот же report.json.
После подготовки выполните scripts/validate-site.py из публичного репозитория,
проверьте интерфейс, затем commit/push разрешённого обновления в main.
Дождитесь успешного Publish dashboard и проверьте открытый сайт.

Проверки кода:

```bash
PATH="$PWD/.venv/bin:$PATH" PYTHONPATH=src .venv/bin/python -m pytest -q
.venv/bin/ruff check src tests
PYTHONPATH=src .venv/bin/mypy src

```
